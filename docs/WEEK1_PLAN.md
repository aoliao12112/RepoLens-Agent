# 第一周开发计划

## 第一天 仓库数据采集

- 完成 GitHub URL 解析和错误处理。
- 接入 GitHub REST API，获取元数据、语言、README 和许可证。
- 写 URL 解析和 API 响应模型测试。

## 第二天 工程信号分析

- 分析目录树中的依赖文件、测试目录、Docker 和 CI 配置。
- 获取近期提交、Release 和 Issue 信号。
- 加入限流提示、超时重试和 SQLite 缓存。

## 第三天 Agent 编排

- 实现规划、维护审查、工程审查和目标适配角色。
- 并行执行互不依赖的审查任务。
- 使用 Pydantic 约束各 Agent 的输出。

## 第四天 证据与防幻觉

- 为事实结论保存来源类型和链接。
- 实现证据校验器，拦截缺少来源的高风险结论。
- 区分事实、推断和待确认信息。

## 第五天 服务与界面

- 实现 FastAPI 任务接口。
- 完成简单 Web 页面，展示执行进度、评分和证据。
- 增加报告导出和人工确认步骤。

## 第六天 评测

- 整理 20 个公开仓库的评测清单。
- 运行批量评测并记录正确率、证据覆盖率、耗时和费用。
- 分析失败案例并修正最突出的问题。

## 第七天 交付

- 补齐测试、README、架构图和演示截图。
- 录制 60 至 90 秒演示视频。
- 执行密钥扫描，检查 Git 历史。
- 根据真实评测结果撰写简历描述和面试问题。
